# The Ten Laws

1. **Optimize for understanding.** Code is read more often than it is written.
2. **Make invalid states difficult to represent.** Types and APIs should prevent mistakes.
3. **Give each unit one responsibility.** Separate rendering, orchestration, transformation, and I/O.
4. **Keep data flow explicit.** Avoid hidden mutation and surprising side effects.
5. **Prefer the platform.** Use language, browser, and platform capabilities before adding abstractions.
6. **Abstract after understanding repetition.** The wrong abstraction costs more than small duplication.
7. **Delete relentlessly.** Dead code, unused dependencies, and obsolete abstractions are liabilities.
8. **Optimize where scale exists.** Preserve readability until runtime scale makes optimization meaningful.
9. **Comments explain decisions.** Code should explain what; comments should explain why.
10. **Consistency beats cleverness.** Familiar patterns reduce cognitive load.
